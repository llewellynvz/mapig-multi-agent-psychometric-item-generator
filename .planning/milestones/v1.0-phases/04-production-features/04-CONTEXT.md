# Phase 4: Production Features - Context

**Gathered:** 2026-03-08
**Status:** Ready for planning

<domain>
## Phase Boundary

Add multi-format export functionality (Markdown, CSV, JSON) to the Results UI, allowing users to download complete item sets with full metadata including items, construct definition, user constraints, evidence sources, validation scores (all 4 dimensions + reasoning), review feedback from all agents, and audit trail (thread_id, run_id, iteration_count, model allocation). Export happens immediately after generation completes without requiring additional configuration.

</domain>

<decisions>
## Implementation Decisions

### Download Button Placement
- **Location:** Bottom of GeneratedItemsTable component (after users review items)
- **Component:** Primary button style using existing `PrimaryButton` component from `@/components/ui/action-buttons`
- **Integration:** Inside table card footer (add CardFooter to existing CardHeader + CardContent structure)
- **Footer content:** Item count summary + download button with format selector
- **Summary format:** "{N} items generated" or "{N} items ({rejected} rejected, {regen} from regeneration)" if applicable

### Format Selection UI
- **Component:** Select dropdown next to Download button (reuse shadcn/ui Select component from Phase 3 model selector)
- **Options:** Three formats with short labels: "Markdown", "CSV", "JSON"
- **Default:** CSV selected by default (analysis-first workflow for Excel/R/Python users)
- **Persistence:** Save format preference to localStorage (same pattern as Phase 3 model selector) with key like `mapig-export-format`
- **Layout:** Horizontal: [Format Selector Dropdown] [Download Button]

### Export Content (All Formats)
- **Scope:** Include everything by default—no user toggles, no section selection
- **Required fields:**
  - Generated items (item_text, rationale, evidence_citations)
  - Construct definition and target population from UserRequest
  - User constraints and construct_exclusions
  - Evidence sources (all EvidenceChunk objects used)
  - Validation scores (all 4 dimension scores + reasoning + attempt count per item)
  - Review feedback (Content, Linguistic, Bias reviewer comments with agent attribution)
  - Audit trail metadata (thread_id, run_id, iteration_count, model allocation info)

### File Naming Convention
- **Pattern:** `{construct_name}_{timestamp}.{ext}`
- **Timestamp format:** `YYYYMMDD-HHMMSS` (e.g., `extraversion_20260308-143022.csv`)
- **Construct name sanitization:** Replace spaces/special chars with hyphens, lowercase
- **No user input:** Automatic naming—no form field, no custom prefix option

### Format-Specific Structure

**Markdown (.md):**
- Human-readable document with headers, lists, tables
- Section structure: Construct Definition → Items → Validation Scores → Review Feedback → Evidence → Audit Trail
- Validation scores: table with dimension | score | reasoning columns
- Review feedback: grouped by agent type with severity indicators

**CSV (.csv):**
- One row per item
- Columns: item_number, item_text, rationale, validation_score, validation_accept, dimension_scores (JSON string), review_comments (JSON string), evidence_citations (comma-separated), attempt_count
- Header row with column names
- Metadata section: separate rows at top with construct_name, construct_definition, target_population, constraints (before item rows)

**JSON (.json):**
- Structured nested object matching FinalOutput schema from backend
- Top-level keys: construct, items, validation, reviews, evidence, audit_trail
- Items array with embedded validation and review objects
- Preserve all nested structures (dimension_scores, review_comments, evidence_chunks)

### Claude's Discretion
- Exact CSV column ordering (prioritize most-used fields left, metadata right)
- Markdown table formatting details (alignment, width)
- JSON indentation (2 spaces vs 4 spaces)
- How to flatten nested validation/review data in CSV (JSON strings vs multiple columns)
- Whether to add "Generated by MAPIG v1.0" footer in Markdown exports
- Error handling for download failures (retry logic, user feedback)

</decisions>

### Established Patterns
- **Results panels:** QualityChecksPanel, EvidenceAuditPanel, FeedbackHistoryPanel show different result facets—export combines all into downloadable file
- **SSE streaming:** ProgressIndicator.tsx displays real-time agent progress—could emit "Generating export..." event if export is slow (likely not needed for client-side formatting)

- **State management:** fullOutput prop in GeneratedItemsTable contains complete FinalOutput object—source of truth for export data

### Integration Points
- **Data source:** `fullOutput?: FinalOutput | null` prop in GeneratedItemsTable contains all export data (items, validation, reviews, evidence, audit trail)
- **Download trigger:** Browser's native download via `<a>` tag with `download` attribute and data URL (`data:text/plain;charset=utf-8,...`) or Blob API
- **Format conversion:** Client-side formatting (TypeScript functions: `exportToMarkdown()`, `exportToCSV()`, `exportToJSON()`)—no backend endpoint needed
- **localStorage key:** Add to same namespace as form fields (e.g., `mapig-export-format` alongside `mapig-instrument-setup`)

</code_context>

<specifics>
## Specific Ideas

- CSV default makes sense for psychometric researchers who typically analyze items in R/SPSS/Excel—prioritize tabular analysis over human readability
- Item count summary in footer provides immediate feedback about what's being exported (especially relevant after rejection/regeneration cycles)
- Dropdown + button layout keeps UI compact while maintaining clear action hierarchy
- Markdown format should look professional enough to share with stakeholders—consider adding timestamp and MAPIG branding at bottom
- File naming with timestamp prevents accidental overwrites when users export multiple variants

</specifics>
