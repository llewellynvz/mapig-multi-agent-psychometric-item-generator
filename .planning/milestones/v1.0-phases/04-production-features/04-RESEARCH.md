**Researched:** 2026-03-08
**Domain:** Client-side multi-format data export (CSV, JSON, Markdown)

## Summary

Phase 4 adds multi-format export functionality to the GeneratedItemsTable component, enabling users to download complete item sets with full metadata (items, construct definition, constraints, evidence sources, validation scores, review feedback, and audit trail) in three formats: CSV (analysis-focused), JSON (machine-readable), and Markdown (human-readable documentation).

This is a pure client-side implementation using browser Blob API and URL.createObjectURL for file downloads. No backend changes are required since all export data is already present in the FinalOutput object. The implementation leverages existing shadcn/ui components (CardFooter, Select) and established patterns (localStorage persistence, PrimaryButton styling).

**Primary recommendation:** Implement RFC 4180-compliant CSV formatting with proper quote escaping, use standard Blob-based download pattern with resource cleanup, persist format preference to localStorage, and structure exports to serve distinct use cases (CSV for statistical analysis, JSON for programmatic access, Markdown for stakeholder documentation).

### Pattern 1: Blob-Based Download with Resource Cleanup
**What:** Create file content as string, convert to Blob with appropriate MIME type, generate temporary URL, trigger download via programmatic anchor click, clean up resources
**When to use:** All client-side file downloads (CSV, JSON, Markdown)
**Example:**
```typescript
// Source: https://dev.to/graciesharma/implementing-csv-data-export-in-react-without-external-libraries-3030
const downloadFile = (content: string, filename: string, mimeType: string) => {
  const blob = new Blob([content], { type: mimeType });
  const url = URL.createObjectURL(blob);
  const anchor = document.createElement('a');
  anchor.href = url;
  anchor.download = filename;
  anchor.click();
  URL.revokeObjectURL(url); // Clean up memory
};

// Usage
downloadFile(csvContent, 'extraversion_20260308-143022.csv', 'text/csv;charset=utf-8');
```

### Pattern 2: RFC 4180 CSV Escaping
**What:** Wrap fields containing special characters (quotes, commas, newlines) in double quotes, escape embedded quotes by doubling them
**When to use:** All CSV field formatting
**Example:**
```typescript
// Source: RFC 4180 (https://www.rfc-editor.org/rfc/rfc4180.html)
const escapeCsvField = (value: string | number): string => {
  if (typeof value === 'number') return String(value);

  // Fields containing quotes, commas, or line breaks MUST be quoted
  const needsQuoting = /[",\r\n]/.test(value);

  if (needsQuoting) {
    // Escape quotes by doubling them
    const escaped = value.replace(/"/g, '""');
    return `"${escaped}"`;
  }

  return value;
};

// Build CSV with proper escaping
const rows = [
  ['Item', 'Rationale', 'Score'],
  [
    'I am outgoing',
    'This item measures "social engagement" which is core to extraversion',
    8.5
  ]
];
const csv = rows.map(row => row.map(escapeCsvField).join(',')).join('\r\n');
```

### Pattern 5: Filename Sanitization
**What:** Remove or replace characters unsafe for filenames, lowercase for consistency, truncate to reasonable length
**When to use:** Generating filenames from user-provided construct names
**Example:**
```typescript
// Source: https://github.com/parshap/node-sanitize-filename (sanitize-filename npm package pattern)
const sanitizeFilename = (name: string): string => {
  return name
    .toLowerCase()
    .replace(/[^a-z0-9]+/g, '-')  // Replace special chars and spaces with hyphens
    .replace(/^-+|-+$/g, '')      // Remove leading/trailing hyphens
    .substring(0, 50);             // Limit length
};

const generateFilename = (constructName: string, extension: string): string => {
  const sanitized = sanitizeFilename(constructName);
  const timestamp = new Date().toISOString()
    .replace(/T/, '-')
    .replace(/:/g, '')
    .replace(/\..+/, '')
    .substring(0, 15);  // YYYYMMDD-HHMMSS
  return `${sanitized}_${timestamp}.${extension}`;
};

// Usage
generateFilename('Extraversion (Big Five)', 'csv')
// => 'extraversion-big-five_20260308-143022.csv'
```

### Anti-Patterns to Avoid
- **Using data URLs for large files:** Blob URLs (URL.createObjectURL) are more memory-efficient than data URLs (data:text/csv;base64,...) for files larger than a few KB
- **Forgetting URL.revokeObjectURL:** Creates memory leak as Blob URLs persist until page unload
- **Backslash escaping in CSV:** Use quote-doubling ("") not backslash (\") - backslash escaping is not RFC 4180 compliant
- **Synchronous localStorage in render:** Access localStorage in useEffect to avoid SSR hydration mismatches in Next.js
- **Not handling localStorage errors:** localStorage can fail in private browsing or when quota exceeded - wrap in try/catch

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| CSV parsing/generation | Custom CSV parser with regex | Native string manipulation with RFC 4180 escaping function | CSV generation is simple (field escaping + joining), but CSV parsing is complex (handles quoted fields, embedded newlines, encoding edge cases) - only need generation for export |
| File download mechanism | Custom iframe injection or form submission | Blob API + URL.createObjectURL | Browser-native, works across all modern browsers, handles binary data, automatic cleanup with revokeObjectURL |
| Format-specific libraries | Papa Parse (CSV), Showdown (Markdown) | Direct string formatting | Adds 30-100KB dependencies for functionality achievable in <50 lines - export formats are predictable, not user-generated |
| User preference persistence | Redux/Zustand for single value | localStorage with try/catch | Single preference value doesn't justify state management library - localStorage is synchronous, simple, and sufficient |

**Key insight:** Export functionality is data transformation (structured object → formatted string) + download trigger (Blob + URL). Libraries add complexity and bundle size for straightforward operations. Use native APIs unless parsing user-uploaded CSV (out of scope for this phase).

## Common Pitfalls

### Pitfall 1: Incomplete CSV Quote Escaping
**What goes wrong:** CSV exports break when item text contains quotes or commas - Excel shows malformed rows, data appears in wrong columns
**Why it happens:** Naive CSV generation joins fields with commas without considering RFC 4180 rules for special characters
**How to avoid:** Always check if field contains quotes, commas, or newlines; if yes, wrap in quotes and double internal quotes
**Warning signs:** Item text "I feel "good" about myself" appears as three separate columns instead of one field
**Prevention:**
```typescript
// WRONG - breaks on special characters
const csv = items.map(item => `${item.item_text},${item.rationale}`).join('\n');

// RIGHT - RFC 4180 compliant
const escapeCsvField = (value: string): string => {
  const needsQuoting = /[",\r\n]/.test(value);
  if (needsQuoting) {
    return `"${value.replace(/"/g, '""')}"`;
  }
  return value;
};
const csv = items.map(item =>
  [item.item_text, item.rationale].map(escapeCsvField).join(',')
).join('\r\n');
```

### Pitfall 2: Memory Leak from Unreleased Blob URLs
**What goes wrong:** Repeated exports cause browser memory to grow unbounded, eventually causing performance degradation or crashes
**Why it happens:** URL.createObjectURL creates persistent references that browser can't garbage collect until manually revoked
**How to avoid:** Always call URL.revokeObjectURL after download completes; Blob URLs only need to exist for the duration of the download click
**Warning signs:** Browser DevTools shows increasing memory usage after multiple exports, user reports browser slowness after generating many exports
**Prevention:**
```typescript
// WRONG - Blob URL leaks memory
const downloadCsv = (content: string, filename: string) => {
  const blob = new Blob([content], { type: 'text/csv' });
  const url = URL.createObjectURL(blob);
  const a = document.createElement('a');
  a.href = url;
  a.download = filename;
  a.click();
  // URL never revoked - memory leak!
};

// RIGHT - Clean up after download
const downloadCsv = (content: string, filename: string) => {
  const blob = new Blob([content], { type: 'text/csv' });
  const url = URL.createObjectURL(blob);
  const a = document.createElement('a');
  a.href = url;
  a.download = filename;
  a.click();
  URL.revokeObjectURL(url); // Release memory immediately
};
```

### Pitfall 3: Missing UTF-8 BOM for Excel Compatibility
**What goes wrong:** CSV files with special characters (accented letters, non-English text) display as garbled characters when opened in Excel
**Why it happens:** Excel assumes ANSI encoding by default unless UTF-8 BOM (Byte Order Mark) is present at file start
**How to avoid:** Prepend '\uFEFF' (UTF-8 BOM character) to CSV content string before creating Blob
**Warning signs:** Non-ASCII characters like "extraversión" display as "extraversiÃ³n" in Excel (but display correctly in Google Sheets or VS Code)
**Prevention:**
```typescript
// WRONG - Excel misinterprets UTF-8 without BOM
const csv = headers.join(',') + '\n' + rows.join('\n');
const blob = new Blob([csv], { type: 'text/csv;charset=utf-8' });

// RIGHT - BOM ensures Excel detects UTF-8
const csv = '\uFEFF' + headers.join(',') + '\r\n' + rows.join('\r\n');
const blob = new Blob([csv], { type: 'text/csv;charset=utf-8' });
```

### Pitfall 4: localStorage Hydration Mismatch in Next.js
**What goes wrong:** Console warnings about hydration mismatch, UI flashes from default value to saved value
**Why it happens:** localStorage is client-only API, not available during server-side rendering - initial render shows default, then useEffect updates to saved value
**How to avoid:** Initialize state to default, load from localStorage in useEffect (after mount), use typeof window check for SSR safety
**Warning signs:** React hydration warnings in console, visible flash from "CSV" to user's saved format on page load
**Prevention:**
```typescript
// WRONG - Reads localStorage during initial render (SSR breaks)
const [format, setFormat] = useState(() => {
  return localStorage.getItem('mapig-export-format') || 'csv'; // Error: localStorage is not defined
});

// RIGHT - Load in useEffect after mount
const [format, setFormat] = useState<string>('csv'); // Default value

useEffect(() => {
  if (typeof window === 'undefined') return; // SSR guard
  try {
    const saved = localStorage.getItem('mapig-export-format');
    if (saved) setFormat(saved);
  } catch {
    // Ignore errors (private browsing, etc.)
  }
}, []);
```

### Pitfall 5: Unsafe Filename Characters
**What goes wrong:** Downloads fail silently or prompt filename with question marks/underscores replacing special characters
**Why it happens:** Operating systems restrict certain characters in filenames (/, \, :, *, ?, ", <, >, |); browser sanitizes automatically but creates ugly names
**How to avoid:** Proactively sanitize construct name before building filename - replace spaces/special chars with hyphens, lowercase for consistency
**Warning signs:** Filename "Social Anxiety: Clinical" becomes "Social Anxiety_ Clinical" (Windows replaces colon) or download fails on certain OS
**Prevention:**
```typescript
// WRONG - Unsafe characters in filename
const filename = `${constructName}_${timestamp}.csv`; // "Social Anxiety: Clinical_20260308.csv" fails

// RIGHT - Sanitize before use
const sanitizeFilename = (name: string) => {
  return name
    .toLowerCase()
    .replace(/[^a-z0-9]+/g, '-')
    .replace(/^-+|-+$/g, '');
};
const filename = `${sanitizeFilename(constructName)}_${timestamp}.csv`; // "social-anxiety-clinical_20260308.csv"
```

```typescript
// Source: RFC 4180 + existing GeneratedItemsTable.tsx pattern (lines 111-127)
import type { FinalOutput } from '@/lib/types';

const exportToCsv = (fullOutput: FinalOutput): string => {
  const escapeCsv = (val: string | number): string => {
    if (typeof val === 'number') return String(val);
    const needsQuoting = /[",\r\n]/.test(val);
    if (needsQuoting) {
      return `"${val.replace(/"/g, '""')}"`;
    }
    return val;
  };

  // Metadata rows at top
  const metadataRows = [
    ['CONSTRUCT', fullOutput.final_items[0]?.construct_name ?? ''],
    ['DEFINITION', fullOutput.final_items[0]?.construct_name ?? ''], // Get from user_request if available
    ['TARGET_POPULATION', ''], // Get from user_request if available
    [''], // Blank separator
  ];

  // Header row
  const headers = [
    'item_number',
    'item_text',
    'rationale',
    'validation_score',
    'validation_accept',
    'attempt_count',
    'dimension_scores',
    'evidence_citations',
    'review_comments'
  ];

  // Data rows
  const dataRows = fullOutput.final_items.map((item, idx) => [
    idx + 1,
    item.item_text,
    item.rationale,
    item.validation_result?.weighted_score.toFixed(2) ?? '',
    item.validation_result?.accept ? 'Yes' : 'No',
    item.validation_result?.attempt ?? 1,
    JSON.stringify(item.validation_result?.dimension_scores ?? []),
    item.evidence_citations.join('; '),
    '' // Review comments would need to be fetched from state
  ]);

  const allRows = [
    ...metadataRows.map(row => row.map(escapeCsv).join(',')),
    headers.map(escapeCsv).join(','),
    ...dataRows.map(row => row.map(escapeCsv).join(','))
  ];

  return '\uFEFF' + allRows.join('\r\n'); // BOM for Excel UTF-8 detection
};
```

### Markdown Export with Structured Sections
```typescript
// Source: Markdown Guide Extended Syntax (https://www.markdownguide.org/extended-syntax/)
const exportToMarkdown = (fullOutput: FinalOutput): string => {
  const sections: string[] = [];

  // Header
  sections.push(`# ${fullOutput.final_items[0]?.construct_name ?? 'Generated Items'}`);
  sections.push('');
  sections.push(`**Generated:** ${fullOutput.audit.timestamp_utc}`);
  sections.push('');

  // Construct Definition
  sections.push('## Construct Definition');
  sections.push(''); // Would pull from user_request
  sections.push('');

  // Items
  sections.push('## Generated Items');
  sections.push('');
  fullOutput.final_items.forEach((item, idx) => {
    sections.push(`### Item ${idx + 1}`);
    sections.push('');
    sections.push(`**Text:** ${item.item_text}`);
    sections.push('');
    sections.push(`**Rationale:** ${item.rationale}`);
    sections.push('');
    sections.push(`**Evidence Citations:** ${item.evidence_citations.join(', ')}`);
    sections.push('');
  });

  // Validation Scores
  sections.push('## Validation Scores');
  sections.push('');
  sections.push('| Item | Score | Accept | Correspondence | Distinctiveness | Clarity | Specificity |');
  sections.push('|------|-------|--------|----------------|-----------------|---------|-------------|');
  fullOutput.final_items.forEach((item, idx) => {
    const val = item.validation_result;
    if (val) {
      const dims = val.dimension_scores;
      sections.push(`| ${idx + 1} | ${val.weighted_score.toFixed(2)} | ${val.accept ? 'Yes' : 'No'} | ${dims[0]?.score ?? '-'} | ${dims[1]?.score ?? '-'} | ${dims[2]?.score ?? '-'} | ${dims[3]?.score ?? '-'} |`);
    }
  });
  sections.push('');

  // Audit Trail
  sections.push('## Audit Trail');
  sections.push('');
  sections.push(`- **Thread ID:** ${fullOutput.audit.thread_id}`);
  sections.push(`- **Run ID:** ${fullOutput.audit.run_id}`);
  sections.push(`- **Iterations:** ${fullOutput.audit.iteration_count}`);
  sections.push(`- **Validation Attempts:** ${fullOutput.audit.validation_attempts ?? 0}`);
  sections.push('');

  return sections.join('\n');
};
```

| Custom CSV parsers with regex | RFC 4180 quote escaping | RFC 4180 published 2005, became standard ~2010 | Interoperability with Excel, Google Sheets, R, Python pandas - consistent parsing across tools |

| Separate export libraries (Papa Parse, FileSaver.js) | Native browser APIs | 2020+ (modern browser baseline) | Reduced bundle size, fewer dependencies, faster load times |

**Deprecated/outdated:**
- **FileSaver.js (saveAs function):** Modern browsers support Blob download natively; library adds 4KB for functionality available in native API
- **msSaveBlob (IE-specific API):** Internet Explorer retired June 2022; no longer needed for browser compatibility
- **data: URLs for file downloads:** Still works but inefficient for files >1MB; Blob URLs handle memory better
