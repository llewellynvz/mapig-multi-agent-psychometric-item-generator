## Architecture Decisions

### Single-Project Vercel Deployment

**Decision**: Deploy as single Vercel project (not two separate projects)

**Context**: Original plan specified two-project setup (frontend + backend as separate Vercel projects)

**Implementation**: Monorepo pattern with Next.js at root and Python serverless functions in `/api`

**Rationale**:
- Vercel natively supports this pattern
- Same-origin architecture (no CORS complexity)
- Simpler environment variable management
- Single deployment, single domain
- Better developer experience for preview deployments

**Impact**: Documented in ARCHITECTURE-DECISION.md and CLAUDE.md

### Native ASGI (Not Mangum)

**Decision**: Use Vercel's native ASGI support

**Context**: Initial plan assumed Mangum adapter needed for FastAPI

**Research Finding**: Vercel has native ASGI support since 2023; Mangum is AWS Lambda-specific

**Implementation**: api/index.py directly exports FastAPI app instance

**Rationale**: Native approach is simpler and officially supported; Mangum would cause deployment failure on Vercel

### Ephemeral Checkpointing (MemorySaver)

**Decision**: Use in-memory checkpoints (not persistent storage)

**Trade-offs**:
- ✅ Simpler deployment (no database setup)
- ✅ Checkpoint logic works during single run
- ❌ Session resumption won't work after cold start
- ❌ Deferred to v2: Vercel Postgres + PostgresSaver

**Rationale**: Acceptable v1 trade-off; session resumption not critical for initial deployment
